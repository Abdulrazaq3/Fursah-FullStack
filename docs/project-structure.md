# هيكلة فرصة والتجهيز للنشر

١٦ أكتوبر ٢٠٢٦

## لماذا جمعنا الواجهة والخلفية؟

نطوّر عقد الاتصال والواجهة والخدمة الخلفية في مجلد واحد، ونراجع التغيير كاملًا. يمكن تشغيلهما على جهاز واحد أو بناء كل جزء ونشره بشكل مستقل. وجودهما في مجلد واحد لا يجبرنا على استضافة واحدة.

## مسؤولية كل جزء

| المجلد | المسؤولية |
|---|---|
| frontend | الملف الشخصي والقيود والطلب، ثم عرض نتائج API وحالات النقص والخطأ |
| backend/app | استقبال الطلب والتحقق من شكله، ثم مستودع الفرص وأدوات البحث والتحقق وسير التوصية عند تنفيذها |
| backend/tests | فحص عقود HTTP والمسارات وحدود جاهزية الخدمة |
| data | البيانات الخام وخطوات تجهيزها؛ لا نغير تواريخ الإعلانات |
| experiments | تجارب محلية معزولة لا تثبت اكتمال التطبيق |
| examples | أربع فرص يدوية مرتبطة بستة مصادر وأدلتها |
| results | نتائج فعلية قابلة للمراجعة |
| docs | التصميم والقرارات وخطوات التنفيذ |
| scripts | أوامر الإعداد والتشغيل والتقييم |
| .local | ملفات محلية كبيرة أو خاصة: أوزان، بيانات اتصال، تشغيل PostgreSQL؛ مستثناة من Git وDocker |

مكتبة `FlagEmbedding/` التي أضافها المستخدم بقيت في مكانها؛ استثنيناها من Git وسياق بناء Docker. التطبيق الحالي لا يعتمد عليها، وتجربة Embeddings تستخدم SentenceTransformers.

## مسار الاتصال

المتصفح ← `frontend/src/api/client.ts` ← `/api/v1/discover` ← `backend/app/routes.py` ← `workflow.py` والأدوات والمستودع عند إكمالها.

محليًا يمر الطلب عبر Vite. في الحاويات يمر عبر nginx إلى خدمة `backend`. الواجهة لا تقرأ PostgreSQL أو أوزان النموذج مباشرة. إعداد `VITE_API_BASE_URL` يُحسم أثناء بناء الواجهة؛ تعديل عنوان API في نشر منفصل يستلزم إعادة البناء.

## ما اكتمل وما ينتظر الربط

واجهة GitHub وعقود FastAPI والبيانات الخام موجودة محليًا. تشغيل الواجهة وإرسال الطلب للخدمة يعمل، والخدمة تُرجع خطأ «غير منفذ» لأن سير التوصية لا يزال تمرينًا مفتوحًا. المسار غير مزود ببيانات توصية بديلة.

تجربة BGE-M3 وpgvector على العينة الصغيرة مكتملة، لكن API لا يستدعيها بعد. عند تنفيذ التكامل ننقل المنطق المناسب إلى وحدات الخدمة ونحافظ على العقود العامة. تحميل النموذج ينبغي أن يكون مرة لكل عامل تشغيل، وليس داخل كل طلب؛ نحدد ميزانية الذاكرة وعدد العمال بعد القياس.

## ملفات التشغيل

- `scripts/setup-fullstack.ps1`: مكتبات API وواجهة React؛ لا ينزّل النموذج ولا يعدّل قاعدة البيانات.
- `scripts/start-backend.ps1`: FastAPI على 127.0.0.1:8000؛ خيار `-Reload` للتطوير.
- `scripts/start-frontend.ps1`: الواجهة على 127.0.0.1:5173.
- `scripts/run-retrieval-experiment.ps1`: تجربة الاسترجاع المستقلة السابقة.
- `backend/Dockerfile` و`frontend/Dockerfile`: بناء منفصل لكل خدمة، من جذر المشروع؛ التشغيل داخل الصور بمستخدم غير root.
- `compose.yaml`: الواجهة والـAPI عبر عنوان واحد. جاهزية العملية تقاس بـ`/health`، بينما `/ready` يظل 503 حتى تنفيذ مكوناته.
- `.github/workflows/ci.yml`: بناء الواجهة وفحوص API وإصلاح مخبأ النموذج وبناء وتشغيل الحاويات عند رفع الملفات إلى مستودع GitHub. لم نرفع أو ننشر هذه التغييرات.

صور API الحالية تحتوي الاعتماديات الأساسية فقط، ولا تحتوي Torch أو BGE-M3 أو قاعدة pgvector. نحدد تجهيز صورة الاستدلال والمخزن عند ربطهما بالخدمة. لا تُنسخ `.local` أو `.env` أو النماذج إلى سياق بناء Docker.
