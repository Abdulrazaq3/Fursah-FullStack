# الخلفية — API وسير التوصية

**السابق:** [التجارب](../experiments/README.ar.md) · **الرئيسي:** [فرصة](../README.ar.md) · **التالي:** [الواجهة](../frontend/README.ar.md)

تحدد خدمة FastAPI حدود الاتصال بالتطبيق: التحقق من الطلبات، وعقود الاستجابة، والأخطاء المنظمة. تصل الواجهة إلى هذه الخدمة، وتنفيذ البحث والتفاصيل وربط تجربة الاسترجاع المحلية هو العمل القادم.

## التشغيل من مجلد المشروع

من جذر المشروع، استخدم بيئة Python المشتركة وأوامر التجهيز والتشغيل:

```powershell
.\scripts\setup-fullstack.ps1
.\scripts\start-backend.ps1
```

يوضح [الدليل الرئيسي](../README.ar.md#start) تشغيل الواجهة في طرفية ثانية.

## إعداد مستقل بديل

استخدم Python 3.11 أو أحدث، من `fursah-fullstack/backend/`:

تحقق أولًا أن إصدار `python3` هو 3.11 أو أحدث. إذا كان أقدم، اختر مفسرًا مناسبًا مثل `python3.12` واستخدمه لإنشاء البيئة. على Windows استخدم `py -3.12 --version` ثم `py -3.12 -m venv .venv` إذا كان هذا الإصدار مثبتًا.

```bash
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -m uvicorn app.main:app --reload --port 8000
```

على Windows استخدم `py -m venv .venv`، ثم `.venv\Scripts\Activate.ps1`، و`Copy-Item .env.example .env` للأوامر المقابلة. انسخ قالب البيئة فقط إذا لم يكن `.env` موجودًا. افتح [توثيق API](http://localhost:8000/docs).

الاعتماديات الأساسية تكفي لتشغيل الهيكل. أضف فقط SDK أو الإطار الذي يحتاجه تصميمك؛ LangChain وLangGraph وPydanticAI وغيرها اختيارات وليست إلزامية. لا توجد قائمة أطر مفروضة، ولا يحدث اتصال بمزود النموذج عند بدء الهيكل.

## ما المتوقع قبل تنفيذ التمرين؟

| المسار | الحالة المتوقعة في نسخة البداية |
|---|---|
| `GET /health` | 200: خادم API يعمل. |
| `GET /ready` | 503: جاهزية التخزين والتطبيق غير منفذة. |
| `POST /api/v1/discover` بطلب صالح | 503 مع `FURSAH_NOT_IMPLEMENTED`. |
| `GET /api/v1/opportunities/{id}` | 503 مع `FURSAH_NOT_IMPLEMENTED`. |
| طلب بحث غير صالح | 422 مع `FURSAH_REQUEST_VALIDATION_ERROR`. |

هذه الأخطاء مقصودة حتى تربط تنفيذك. ابدأ بمسار واحد يعمل من مصدر خام إلى استجابة API، ثم وسّعه.

## ما الذي يجب أن يبقى متوافقًا؟

يحدد `app/schemas.py` نماذج الطلبات والاستجابات العامة التي تستخدمها الواجهة. يوفر `main.py` و`routes.py` اتصال HTTP. حافظ على توافق عناوين المسارات ومعاني الاستجابات وأنواعها. يحتوي `internal.py` على أمثلة أنواع داخلية اختيارية، وليس مخطط قاعدة بيانات أو حالة وكيل مفروضين.

| نقطة بداية اختيارية | المدخل والمسؤولية | المخرج |
|---|---|---|
| `repository.py` | التخزين ومعايير البحث أو معرف الفرصة | أدلة داخلية أو تفاصيل عامة |
| `agent.py` | السياق وإعداد عميل النموذج وتعليماته | نتيجتك الداخلية |
| `tools.py` | معاملات الأدوات واعتماديات التطبيق | ملاحظاتك وأدلتك |
| `validation.py` | النتائج المقترحة والأدلة | نتيجة التحقق الخاصة بك |
| `workflow.py:discover` | الطلب العام والاعتماديات | `DiscoveryResponse` |
| `internal.py` | تصميم المخطط | أنواع داخلية قابلة للاستبدال |
| `../data/data_exploration_and_preparation.ar.ipynb` | الإعلانات الخام | تجهيزك للبيانات وتخزينها |

يمكن دمج ملفات المتدرب أو تقسيمها أو إعادة تسميتها أو استبدالها. هذه مواقع مقترحة **وليست مسارًا إلزاميًا**. حدّث `routes.py` وربط الاعتماديات إذا نقلت نقاط الدخول. لا تملأ المسارات غير المكتملة بتوصيات ناجحة وهمية.

<a id="first-working-integration"></a>
## أول ربط يعمل

1. أكمل عينة الدفتر وأضف إلى ملاحظات المصادر الحقائق التي يحتاجها التطبيق.
2. اقرأ مخزنك المختار في `repository.py`. نفّذ `get_details(id)` ليعيد `OpportunityDetailsResponse` لسجل فعلي، أو `None` إذا لم يوجد المعرّف.
3. جرّب المعرّف في `/docs`. استخدم دليلًا فعليًا؛ الأمثلة التالية ليست سجلات جاهزة لتقديمها للمستخدم.
4. اربط `discover(request, deps)` بمنطق الاسترجاع واتخاذ القرار. لا يصل النموذج إلى بياناتك تلقائيًا؛ يجب أن تزوده شيفرتك بالأدلة المسترجعة أو أدوات الوصول إليها.
5. حوّل النتيجة إلى `DiscoveryResponse` ثم جرّب الطلب نفسه من الواجهة. اجعل الجاهزية تعكس المكونات المنفذة فعلًا.

لا يلزم أن تشبه سجلاتك الداخلية JSON الاستجابة. يتم التحويل عند حدود المستودع وسير العمل. يمكنك اختيار الاسترجاع ثم اختيار النموذج، أو وكيل بأدوات، أو تصميم آخر.

### مثالان للقيود والأدلة

- المدينة المحفوظة الرياض والطلب «جدة هذه المرة». بعد حسم الطلب، مرّر **القيود المحسومة نفسها إلى التصفية والترتيب** دون تغيير التفضيلات المحفوظة. التعارض غير المحسوم يعيد `needs_info` مع `constraint_conflict: true` والحقل `constraints.location_preference`.
- المصدر يقول «معرفة Python مطلوبة». أبقِ الشرط ظاهرًا ولا تضف شرط عمر أو سنة دراسية. اسأل عن المهارات الناقصة فقط عند الحاجة للقرار، ولا تطلب مستوى المهارة إلا إذا احتاجه شرط مدعوم بالمصدر. تبقى الأهلية غير المثبتة غير مؤكدة.

## التخزين والجاهزية

`DatasetLoader` مساعد اختياري لقراءة CSV وJSON. المسار `data/prepared/opportunities.json` مثال للفرق التي تختار JSON؛ ليس شرطًا لبدء التشغيل أو الجاهزية. يمكن لتخزين آخر الاستغناء عنه.

نفّذ نقطتي التوسعة القابلتين للاستبدال:

- `repository.is_ready()`: تحقق من إمكانية الوصول إلى تخزينك ووجود المعلومات التي يحتاجها تنفيذك.
- `workflow.application_is_ready(deps)`: تحقق من جاهزية مكونات التطبيق وإعداداته، بما فيها عميل النموذج إن احتجته.

تعيدان قيمًا منطقية فعلية. يعيد `/ready` الرمز 200 فقط إذا أعادتا `True`. التنفيذ الناقص أو الفشل أو `False` يؤدي إلى 503 مع توضيح آمن. لا تعد `True` دون فحص. الجاهزية تشغيلية وليست دليلًا على صحة التوصيات؛ اجعل الفحوص محدودة ولا تستدعِ نموذجًا مدفوعًا مع كل طلب صحة.

### بدء الموارد وإغلاقها

يمكن لتطبيقك فتح التخزين والعملاء غير المتزامنين أثناء startup/lifespan وإغلاقهم عند الإنهاء. اجعل الطلبات تستخدم الموارد ضمن دورة الحياة المتوافقة معها. لا تفتح اتصالًا جديدًا لكل خطوة بلا حاجة، ولا تستخدم موارد بعد إغلاقها.

## الإعدادات وتهيئة النموذج

يتضمن `.env.example` حقول نموذج اختيارية وإعدادات التشغيل. هيّئ العميل في المكان المناسب لتصميمك؛ `agent.py` مجرد اقتراح. يسهل `deps.model_config` إعداد مزود بمفتاح API أو عميل محلي عبر loopback مفعّل صراحة. استبدله إذا اخترت مصادقة أخرى. لا يمنع غيابه تشغيل الهيكل أو فحص الجاهزية. لا تضع بيانات الاعتماد في الواجهة أو سجلات المصادر أو السجلات التشغيلية.

`FURSAH_FRAMEWORK_TRACK` وصف اختياري، لا مفتاح ينفذ إطارًا تلقائيًا. يحدد `FURSAH_DATA_DIR` ملفات البيانات بالنسبة إلى `fursah-fullstack/`. يحدد `FURSAH_ALLOWED_ORIGINS` مصادر الواجهة المسموحة. حدود النموذج ومسار العمل إعدادات على المتدرب تطبيقها وليست تنسيق تنفيذ تلقائيًا.

<a id="evaluation-time"></a>
## سياسة وقت التقييم

اترك `FURSAH_EVALUATION_TIME` فارغًا لاستخدام وقت الطلب الحقيقي. اختار المنظم **18 أكتوبر 2026** للصف مع الإبقاء على الساعة 12 ظهرًا في الرياض:

```dotenv
FURSAH_EVALUATION_TIME=2026-10-18T12:00:00+03:00
```

استخدم القيمة في بيئة التمرين المحلية أو المنشورة فقط؛ يظل الافتراضي الفارغ هو الوقت الحقيقي. أعد تشغيل الخادم بعد تغيير الإعدادات. يلتقط المسار `deps.evaluation_time` مرة واحدة لكل طلب؛ أعد استخدامه في الأدوات والقرارات. تُرفض القيم التي لا تتضمن منطقة زمنية. لا تغيّر تواريخ البيانات. قارن موعدًا نهائيًا بدقة فقط إذا كان المصدر يحدد التاريخ والوقت والمنطقة؛ بلوغ لحظة الإغلاق يعني انتهاء الموعد، والحقائق الناقصة تبقى غير مؤكدة.

راجع [تمرين البيانات](../data/README.ar.md) لمعالجة المواعيد المنتهية والحالات غير المؤكدة. احتفظ بتواريخ المصادر كما هي.

## أمثلة العقد العام

الأمثلة توضح الصيغ فقط؛ ليست إجابات للبيانات أو حلول ترتيب وأهلية. راجع الحقول المطلوبة والقيم الافتراضية في `/docs` و`app/schemas.py`.

**طلب البحث:** `POST /api/v1/discover`

```json
{"request_id":"example-1","query":"أبحث عن ورشة","profile":{"interests":[],"skills":null},"constraints":{}}
```

**مثال استجابة HTTP 200 لطلب معلومات إضافية:**

```json
{"request_id":"example-1","status":"needs_info","message":"هل لديك معرفة Python المطلوبة في الإعلان؟","recommendations":[],"missing_fields":["profile.skills"]}
```

**مثال صيغة نتيجة HTTP 200؛ المحتوى توضيحي فقط:**

```json
{"request_id":"example-1","status":"ok","message":"مثال لتنسيق الاستجابة فقط","recommendations":[{"opportunity_id":"EXAMPLE","title":"عنوان توضيحي","eligibility_status":"uncertain","reason":"نص توضيحي وليس قرار أهلية","source_ids":["EXAMPLE-SOURCE"]}],"missing_fields":[]}
```

**مثال HTTP 200 دون تطابق تدعمه الأدلة:**

```json
{"request_id":"example-1","status":"no_match","message":"لم نجد فرصة تدعم الأدلة مطابقتها لطلبك","recommendations":[],"missing_fields":[]}
```

استخدم `needs_info` عندما تستطيع إجابة المستخدم حل معلومة ناقصة ذات صلة، وليس بديلًا لأخطاء مزود النموذج أو لكل نقص في المصادر. يطلب المثال السابق المهارات لأن مصدرًا افتراضيًا يشترط Python، لا لأن كل بحث يحتاج مهارات.

**طلب التفاصيل:** `GET /api/v1/opportunities/EXAMPLE` دون جسم طلب.

**مثال استجابة التفاصيل HTTP 200:**

```json
{"opportunity_id":"EXAMPLE","title":"عنوان توضيحي","source_ids":["EXAMPLE-SOURCE"],"topics":[],"required_skills":null,"eligibility_requirements":{"mandatory":null,"preferred":null},"data_warnings":[]}
```

قبل التنفيذ، يعيد البحث HTTP 503:

```json
{"request_id":"example-1","status":"error","message":"The FURSAH discovery workflow is intentionally unfinished in the starter.","recommendations":[],"missing_fields":[],"error_code":"FURSAH_NOT_IMPLEMENTED"}
```

وتستخدم التفاصيل صيغة الخطأ العامة، أيضًا HTTP 503 ما دامت غير منفذة:

```json
{"request_id":"example-1","error_code":"FURSAH_NOT_IMPLEMENTED","message":"The details implementation is unfinished.","details":[]}
```

قد تختلف الرسائل ومعرفات الطلبات المولدة. الطلب غير الصالح يعيد 422 مع `FURSAH_REQUEST_VALIDATION_ERROR`. بعد إكمال المستودع، تُعاد 404 إذا لم توجد الفرصة.

## التحقق من المعنى ومخرجات النموذج

مطابقة JSON للنوع لا تثبت أن النموذج فهم الطلب. إذا طلب المستخدم جدة وأسقطها النموذج، فقد تكون الاستجابة صحيحة شكليًا لكنها خاطئة معنويًا. تحقّق من القيود الصريحة قبل التصفية والترتيب، واعرض القيود التي فهمتها. انتبه للنفي والبدائل؛ لا تفرض قاعدة بحث جزئي على كل العربية.

تحقّق من أن المعرفات المختارة ضمن المرشحين، والأدلة تخصهم، والاقتباسات تطابق مصادرها. عند الفشل يمكنك إعطاء ملاحظات محددة للنموذج وإعادة المحاولة ضمن حد معلوم؛ بعد استنفاده أعد خطأ مضبوطًا. لا تُرجع نتيجة غير مدعومة لمجرد تجنب الخطأ. إذا طلبت مهارات ناقصة، اشرح المهارات المطلوبة وسبب الحاجة إليها دون طلب حقول لا تجمعها الواجهة.

اختر مكتباتك وفق إصدار SDK المثبت، وثبّت الإصدارات التي جربتها في متطلبات تنفيذك. ضع أسماء الحزم ذات الإضافات بين علامات اقتباس في الطرفية، مثل `'package[extra]'`. قِس زمن الاسترجاع والنموذج منفصلين، وحدّد المحاولات والمهلة الإجمالية.

## معاني مهمة

المهارات `null` تعني أن المستخدم لم يجب، و`[]` تعني اختيار عدم وجود مهارات صراحة. لا تطلب حقولًا لا تجمعها الواجهة. الأهلية مختلفة عن حالة التسجيل. المتطلبات الإلزامية والتفضيلية قوائم عبارات مدعومة بالمصادر أو `null`. المدة عدد صحيح موجب بالأيام أو `null`؛ الساعات والجلسات حقائق منفصلة.

يحدد `evidence_version` اختياريًا نسخة حقائق المصدر التي بنيت عليها التوصية أو التفاصيل. غيّره عند تغير الأدلة ذات الصلة. تحتفظ الواجهة بتأكيد سابق فقط عند تطابق معرفات المصادر والنسخ غير الفارغة والحقائق المعروضة. غياب النسخة مقبول في العقد لكنه يمنع الإبقاء على التأكيد في التفاصيل. طريقة التقديم والحضور الفعلي حقيقتان منفصلتان، والتعارض يؤدي إلى عدم اليقين.

## حل مشكلات التشغيل

| العَرَض | ما الذي تراجعه؟ |
|---|---|
| لا يمكن الوصول إلى `/health` | شغّل uvicorn من `backend/` وراجع المنفذ وبيئة Python. |
| ظهور `FURSAH_NOT_IMPLEMENTED` | أكمل نقطة التنفيذ المذكورة؛ هذا متوقع قبل التنفيذ. |
| التفاصيل لا تجد السجلات المجهزة | راجع مسار التصدير أو المخزن وربط المستودع. حفظ مخرجات الدفتر لا يربط التخزين. |
| فشل مصادقة مزود النموذج | راجع المزود وعنوانه واسم النموذج وطريقة المصادقة في إعدادات الخادم. لا تكشف بيانات الدخول في المتصفح. |
| فشل التحقق من مخرجات النموذج | قارنها بنوع المخرجات الداخلي ثم حوّلها إلى عقد الاستجابة العام. |
| البحث يستغرق وقتًا طويلًا | قِس زمن الاسترجاع والنموذج منفصلين، وأعد استخدام العملاء المناسبين وحدّد المحاولات والمهل. |

راجع [قيم حالة التسجيل المعروضة](../frontend/README.ar.md) عند تحويل حالاتك الداخلية. انقضاء تاريخ الفتح وحده لا يثبت أن التسجيل مفتوح الآن.

## تجربة التنفيذ

استخدم الأمثلة و`/docs` لفهم العقد. فحوص الاتصال وحدود API الحالية محفوظة في [سجل التحقق](../docs/fullstack-verification.md)، وتنفيذ سلوك التوصية الكامل وتقييمه هما العمل القادم.
