# التتبّع — شاهد مراحل الطلب

[دليل التقييم](../../../evals/README.ar.md) · [الخلفية](../../README.ar.md)

يمثل **trace** أثر الطلب، ويمثل **span** قياس عملية داخله. نسجل الفهم والتضمين والاسترجاع وإعادة الترتيب وفحص المرشحين والاختيار لتفسير الإخفاق والزمن المستغرق.

| الملف | دوره |
|---|---|
| [spans.py](spans.py) | قياس المراحل ومخرجات التقييم |
| [phoenix.py](phoenix.py) | ربط OpenTelemetry بـPhoenix |
| [../catalog_workflow.py](../catalog_workflow.py) | استدعاءات `eval_span` حول مراحل التنفيذ الفعلية |

نفّذ `./evals/run.ps1 -Demo -Open` من جذر المستودع. في Phoenix افتح **fursah-eval → eval.case**. افحص spans لمعرفة المراحل البطيئة، ثم annotations لفهم الدرجات. مثلًا: قد يكون الاسترجاع سريعًا بينما تستغرق إعادة الترتيب معظم وقت الطلب.

يعرض Phoenix القياسات ولا يثبت جودة الإجابة وحده؛ توفر [فحوص الكود](../../../evals/catalog_graders.py) الدرجات. تُفعّل المخرجات التفصيلية للتقييم الاصطناعي، وتبقى معطلة في الاستخدام العادي.
